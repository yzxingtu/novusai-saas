# 项目背景与文档规范（脊柱侧弯矫形器自动建模）

## 开发前必读

在开始编写或修改代码前，请先阅读并理解：

1. 仓库根目录 **README.md**：项目简介、业务目标、技术栈（交互层 / 建模引擎 / 特征提取 / 数据处理 / 基础设施）、核心模块划分。
2. **docs/** 下已有文档：按目录主题浏览，避免重复造轮子或与既定架构冲突。

若 README 或 docs 与代码不一致，优先澄清或更新文档后再实现。

## 文档存放规范

项目文档分为两个体系，各自有独立用途与生成方式：

### 1. 人工编写的项目文档 → `docs/`

- 由团队成员手动编写和维护的项目文档（架构说明、API 契约、开发指南、决策记录、运维说明等）放在 **`docs/`** 目录下。
- **不得在仓库根目录随意新增散落的 `.md` 文件**（根目录仅保留 `README.md` 作为入口）。
- 按主题分子目录分类存储，命名使用小写英文与连字符：

| 目录 | 用途 |
| :--- | :--- |
| `docs/architecture/` | 系统架构、模块边界、数据流 |
| `docs/api/` | 接口契约、OpenAPI/示例请求 |
| `docs/development/` | 环境搭建、本地运行、贡献流程、代码规范 |
| `docs/guides/` | 面向使用者或协作方的操作指南 |
| `docs/decisions/` | ADR / 重大技术或产品决策摘要 |
| `docs/research/` | 算法与文献笔记（可选，按需使用） |

- 新增文档时：选择合适子目录；文件名语义清晰；必要时在 **`docs/README.md`** 中增加索引条目。

### 2. 智能体自动生成的知识文档 → `.qoder/repowiki/`

- 由 AI 智能体通过工具自动分析代码库后生成的项目知识文档，统一存放在 **`.qoder/repowiki/`** 目录中。
- **智能体自行决策生成时机与内容**：当代码发生结构性变更（新增模块、重构接口、修改数据模型等）时，智能体应主动判断是否需要更新 repowiki 中对应的文档。
- 目录结构按语言与主题组织（如 `zh/content/系统架构/`、`zh/content/API接口文档/` 等），由智能体根据变更范围自动维护。
- `repowiki/` 下的文档是代码的**镜像与索引**，帮助智能体快速理解项目全貌，与 `docs/` 中的人工文档互补而非替代。

### 两者关系

| | `docs/` | `.qoder/repowiki/` |
| :--- | :--- | :--- |
| 编写者 | 团队成员手动 | AI 智能体自动 |
| 用途 | 项目规范、决策、指南 | 代码知识索引、模块速览 |
| 更新时机 | 随需求/决策手动更新 | 代码结构变更时智能体自动判断更新 |
| 是否提交 | 是 | 是（随仓库共享） |

## 编写习惯

- 先对齐 README 中的目标与验收标准，再落代码或文档。
- 文档与代码变更尽量在同一任务中同步，避免「代码已改、文档过期」。
