# 管理端 Codegen 三页布局重构方案（2026-03-23）

## 1. 目标

本次不是继续在现有页面上补卡片、补提示、补视觉层，而是把已经失控的三页布局重新收回到项目现有管理端规范内：

1. `http://localhost:5666/admin/system/codegen`
2. `http://localhost:5666/admin/system/codegen/new?preset=tree`
3. `http://localhost:5666/admin/system/codegen/8/edit`

要求：

1. 主操作区必须优先可用，不能再被头部展示区、状态卡、侧栏摘要挤压。
2. 列表页回到“表格优先”，Builder 回到“配置优先”，预览只作为辅助，不再抢占首屏。
3. 所有 icon 必须使用本地可用子集，禁止触发被拦截的在线 Iconify 请求。
4. 新建与编辑页必须统一结构，不能出现“新建一套、编辑一套、再额外堆一层审计卡片”的分裂状态。

---

## 2. 实际审计结论

### 2.1 列表页问题

页面：`/admin/system/codegen`

已确认问题：

1. 信息层级倒置。
   - 顶部大 Hero、5 张大状态卡、右侧关注面板占据首屏主体。
   - 真正高频操作区是搜索、筛选、表格与行操作，但被压缩到页面下半段。
2. 两栏布局不适合当前数据量。
   - 右侧“最近关注事项”长期占宽，导致左侧表格区被压窄。
   - 当前列表只有 1 条数据尚且拥挤，数据量上来会更差。
3. icon 规范违规。
   - 控制台已确认有两条警告：
     - `lucide:flask-conical`
     - `lucide:file-json-2`
   - 这说明当前实现没有严格遵循“只用本地子集图标”的项目规范。

### 2.2 Builder 页问题

页面：

1. `/admin/system/codegen/new?preset=tree`
2. `/admin/system/codegen/8/edit`

已确认问题：

1. 主操作入口被展示卡挤压。
   - 顶部大 Hero + 右上 4 张指标卡占据过高垂直空间。
   - 资源名、模块、显示名、保存、生成等真正关键动作被压成一条细工具带。
2. 同一信息重复出现 3 次。
   - 顶部 Hero 展示一次状态。
   - 右侧“配置检查面板”又展示一次摘要。
   - 底部条还在继续展示入口数、字段数、Admin/Tenant、表格/卡片。
3. Builder 焦点错误。
   - 代码生成器本质上是“配置页面”，但当前中间默认展示的是大预览区。
   - 字段管理却被折叠在“字段管理”按钮后面，不是默认工作区。
4. 区域职责混乱。
   - 左侧是组件库。
   - 中间既承担预览，又承担字段管理切换。
   - 右侧未选中字段时继续叠摘要卡。
   - 底部还保留第二套动作条。
   - 结果是所有区都在说话，但没有一个区是明确的主工作区。
5. 首屏视觉“轻内容、重装饰”。
   - 大面积淡色 Hero + 指标卡 + 空白背景，视觉占比很大。
   - 真正需要高密度展示的字段、属性、结构配置反而在小区域里拥挤。

### 2.3 运行时结论

实际浏览器审计结论：

1. 初始加载没有出现阻断式 JS error。
2. 当前最明确的控制台问题是图标在线请求被拦截。
3. 用户体感里的“页面乱、主体被遮挡”，主要来自结构性布局失衡，而不是单一运行时报错。

## 3. 这次重构的明确原则

### 3.1 列表页原则

列表页必须回到项目现有后台常规模式：

1. 顶部只保留紧凑标题区。
2. 摘要统计采用一行紧凑卡片，不再使用大 Hero。
3. 表格是页面绝对主体。
4. 关注事项改成表格上方的紧凑提醒，不再长期占右侧栏。

### 3.2 Builder 原则

Builder 必须回到“配置工作台”而不是“展示板”：

1. 顶部是紧凑状态条，不再是大 Hero。
2. 默认工作区必须是“字段列表”，不是预览。
3. 预览保留，但降级为工作区 Tab，不再霸占默认主视图。
4. 右侧只保留一个明确职责：
   - 选中字段时：字段属性编辑
   - 未选中字段时：配置检查与快捷入口
5. 底部重复动作条全部删除或最小化，只保留必要状态。

### 3.3 规范对齐原则

1. 图标只使用本地子集内已有图标。
2. 布局语义对齐现有后台：
   - `Page`
   - 上方紧凑标题/说明/操作
   - 主卡片承载核心内容
3. 不再引入新的全局状态管理方案。
4. 尽量复用已有模块，只重构容器与信息结构。

## 4. 具体重构方案

### 4.1 列表页重构

目标结构：

1. 顶部 Header Card
   - 左：页面标题 + 一句说明
   - 右：`从数据库导入`、`新建配置`
2. 紧凑状态条
   - 草稿
   - 已生成
   - 已应用
   - 可回滚
   - 需关注
   - 保留点击筛选，但尺寸收紧
3. 关注事项 Alert
   - 如果存在最近错误或删除保护，只显示一条紧凑摘要
   - 点击可切换到 attention 筛选
4. 主表格 Card
   - 搜索、筛选、表格、分页放回同一卡片
   - 不再使用右侧长期固定的 second panel

删除项：

1. 顶部大渐变 Hero
2. 右侧常驻“最近关注事项”侧栏
3. 使用 `lucide:flask-conical`
4. 使用 `lucide:file-json-2`

### 4.2 Builder 页重构

目标结构：

1. 顶部 Compact Header
   - 标题：资源名 / 新建配置
   - 次级信息：模块、显示名、状态 tag
   - 右侧：返回、保存草稿、生成代码、更多
   - 不再有大块 Hero 和 4 张指标卡
2. 主体三栏
   - 左栏：基础配置 + 组件库
   - 中栏：工作区
   - 右栏：属性 / 检查

#### 左栏

拆成两个 card：

1. 基础配置 Card
   - 资源名
   - 模块
   - 中文显示名
   - 英文显示名
   - 复数路由
   - Admin/Tenant
   - 表格/卡片
2. 组件库 Card
   - 搜索
   - 分组列表
   - 尺寸缩窄但信息更清晰

#### 中栏

工作区改为显式 Tab：

1. 字段列表
2. 列表页
3. 新建表单
4. 详情

规则：

1. 默认进入“字段列表”
2. 字段列表承载最主要的 schema 编辑能力
3. 列表页/新建表单/详情只作为预览工作区
4. 不再使用“字段管理 / 返回预览”的二元切换按钮作为主入口

#### 右栏

保持一栏，但收紧内容：

1. 选中字段：
   - 字段属性面板
2. 未选中字段：
   - 配置检查面板
   - 最近预览摘要
   - 快捷入口（高级配置、DB 导入、YAML 导入、定位错误）

删除项：

1. 底部重复动作条中的 `DB 导入 / 高级配置 / 预览`
2. 顶部大 Hero
3. 右上 4 张大指标卡
4. 中央“字段管理”覆盖式工作流

### 4.3 组件库与字段列表视觉方向

组件库不再像“散装折叠列表”，而要更像真实工具箱：

1. Card 化容器
2. 分组标题更清晰
3. 条目高度减小
4. 只保留必要 icon 与名称，不堆装饰

字段列表要成为主工作区：

1. 默认打开
2. 支持卡片 / 表格两视图保留
3. 顶部显示字段数量与关键批量切换
4. 让用户进来第一眼看到 schema，而不是 preview

## 5. 实施顺序

### Phase A. 先修硬问题

1. 替换违规 icon
2. 删除列表页右侧常驻侧栏
3. 删除 Builder 顶部大 Hero 与右上大指标卡
4. 删除 Builder 底部重复动作条

### Phase B. 重建主工作区

1. 列表页改成单列结构
2. Builder 左栏拆成“基础配置 + 组件库”
3. Builder 中栏改成“字段列表 / 列表页 / 新建表单 / 详情”工作区 Tab
4. Builder 右栏保留属性/检查二态

### Phase C. 收尾

1. 补 i18n 文案
2. 浏览器复查三页
3. `vue-tsc` 校验

---

## 6. 完成定义

本次改造只有满足以下条件，才算完成：

1. 列表页首屏看到的是标题、紧凑状态条、搜索与表格，而不是大面积展示 Hero。
2. 新建/编辑页首屏看到的是紧凑头部和明确主工作区，不再被大卡片挤压。
3. 字段列表成为 Builder 默认工作区。
4. 右侧检查区不再和顶部/底部重复表达同一批状态。
5. 控制台不再出现 codegen 页面的在线 Iconify 请求告警。
6. `vue-tsc` 通过。
