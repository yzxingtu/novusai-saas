# 租户端架构原则

## 核心理念

**租户的价值不在于"创建工具"，而在于"使用工具 + 提供业务知识"**

租户通过平台提供的智能体和技能包获得 AI 能力，通过上传业务文档到知识库来注入领域知识。
租户不应能够创建可执行任意代码或发起网络请求的工具。

## 权限边界

### 租户端【允许】
- 查看和使用平台分配的智能体
- 配置智能体访问权限（`tenant_role_ids` / `user_role_ids`）
- 调整智能体内存开关、配额参数
- 管理自有知识库（上传、检索、删除文档）
- 创建和管理自有用户角色、成员
- 查看对话历史和调用日志

### 租户端【禁止】
- 创建/编辑/删除技能包（SkillPackage CRUD）
- 创建/编辑技能（Skill CRUD）
- 绑定/解绑技能包到智能体（只能查看平台绑定的包）
- 创建智能体（待讨论 — 如允许，智能体只能绑定平台提供的技能包）
- 安装或启用插件

### 理由（安全）
- HTTP 工具类技能可被用于 SSRF 攻击，让平台服务器访问内网服务
- 数据智能技能可通过自然语言→SQL 探测平台元数据
- 知识库类技能相对安全（仅读取租户自己的文档）
- 最小权限原则：给租户恰好够用的能力，不多不少

## 技能包分配模型

```
Platform Admin → 创建系统技能包（HTTP/数据/知识库/Toolkit）
             ↓
Platform Admin → 将技能包分配给租户（scope=assigned_tenants 或 admin_and_all）
             ↓
Tenant → 查看和使用已分配的技能包（通过平台智能体）
             ↓
Tenant → 上传业务文档到知识库 → RAG 检索增强
```

## 知识库扩展（允许）

租户可以：
- 创建知识库（Knowledge Base）并上传文档
- 将知识库与平台智能体绑定（租户级 RAG 配置）
- 这是租户注入"业务知识"的合法、安全通道

## 智能体管理（条件允许）

如果允许租户创建智能体：
- 只能绑定平台已分配的技能包（不能绑定自建包）
- 不能修改技能包内的技能配置
- 只能调整模型参数、提示词、配额等文本配置
