# 企业端架构原则

## 核心理念

**企业的价值不在于"创建工具"，而在于"使用工具 + 提供业务知识"**

企业通过平台提供的智能体和技能包获得 AI 能力，通过上传业务文档到知识库来注入领域知识。
企业不应能够创建可执行任意代码或发起网络请求的工具。

## 权限边界

### 企业端【允许】
- 查看和使用平台分配的智能体
- 配置智能体访问权限（`tenant_role_ids` / `user_role_ids`）
- 调整智能体内存开关、配额参数
- 管理自有知识库（上传、检索、删除文档）
- 创建和管理自有用户角色、成员
- 查看对话历史和调用日志

### 企业端【禁止】
- 创建/编辑/删除技能包（SkillPackage CRUD）
- 创建/编辑技能（Skill CRUD）
- 绑定/解绑技能包到智能体（只能查看平台绑定的包）
- 创建智能体（待讨论 — 如允许，智能体只能绑定平台提供的技能包）
- 安装或启用插件

### 理由（安全）
- HTTP 工具类技能可被用于 SSRF 攻击，让平台服务器访问内网服务
- 数据智能技能可通过自然语言→SQL 探测平台元数据
- 知识库类技能相对安全（仅读取企业自己的文档）
- 最小权限原则：给企业恰好够用的能力，不多不少

## 技能包分配模型

```
Platform Admin → 创建系统技能包（HTTP/数据/知识库/Toolkit）
             ↓
Platform Admin → 将技能包分配给企业（`scope=selected_tenants` 或 `admin_and_selected_tenants` + `resource_tenant_assignments`）
             ↓
Tenant → 查看和使用已分配的技能包（通过平台智能体）
             ↓
Tenant → 上传业务文档到知识库 → RAG 检索增强
```

## 知识库扩展（允许）

企业可以：
- 创建知识库（Knowledge Base）并上传文档
- 将知识库与平台智能体绑定（企业级 RAG 配置）
- 这是企业注入"业务知识"的合法、安全通道

## 回收站边界

- 企业端和管理端的普通 CRUD 页面统一使用**模块回收站弹窗**，不要为企业端再做独立的“总回收站”页面。
- **总回收站只有一个**，并且只在管理端展示：`/admin/system/recycle-bin`。
- 企业端**不存在** `/tenant/system/recycle-bin`；即使给企业端增加权限，也不应放开该入口。
- 企业端或管理端在模块回收站里执行二次删除后，记录都进入管理端总回收站，由平台统一恢复或彻底清理。
- 企业端文案应明确说明“30 天后转入管理端总回收站，由平台统一处理”，禁止暗示企业管理员可以自行进入总回收站。

## 智能体管理（条件允许）

如果允许企业创建智能体：
- 只能绑定平台已分配的技能包（不能绑定自建包）
- 不能修改技能包内的技能配置
- 只能调整模型参数、提示词、配额等文本配置
